# PixelScope v0.2.0

Release date: Pending release acceptance (source notes prepared 2026-11-19)

Source commit: `{{SOURCE_COMMIT}}`

## Overview

This Core release candidate consolidates the first major post-v0.1.0 improvements to the Windows image inspection, comparison, and evidence-review workflow. It is the PUBLIC Core/Reference release line; Enterprise IQA implementation, PRIVATE service configuration, and its four-part distribution version remain downstream-owned.

## User-visible changes

- **Physical-pixel comparison and navigation:** improved consistent 100%/200%/400% viewing, source-relative view-state restoration, stable Reference/Target selection and Difference presentation, and preserved physical zoom/center during comparison and layout changes.
- **Source identity and analysis:** clearer source aliases, compact labels without duplicated parent-directory prefixes, consistent Statistics/Histogram/Line Profile presentation, and source/metric comparison pivot and export workflow.
- **RAW/YUV input:** reusable interpretation profiles and multi-file profile application with validation, bounded asynchronous preview, and safer RAW dialog sizing across GRAY/BAYER layout changes and small screens.
- **Memo and ROI evidence:** simplified current-context ROI recording with multiple selectable/editable ROIs; labeled crop views; save/reopen of portable Memo evidence; readable offline HTML with crop PNGs, optional native Statistics/CSV and preview-quality information where available.
- **Recent items and startup:** lexical history handling avoids blocking filesystem resolution during startup when a previously used UNC share is disconnected. Explicit Recent Folder/Session and file-dialog directory checks use bounded preparation off the GUI thread.
- **UI usability:** narrow-window ROI bounds reflow, more legible collision-aware ROI labels, report navigation and asset links, and multiple presentation/toolbar consistency corrections.

Release-candidate preparation and hosted PR CI are not equivalent to a fully qualified Windows installer release. The authorized Windows release operator must verify:

1. Exact candidate commit, canonical version/release-note consistency, release candidate provenance and source-commit marker replacement.
2. Applicable Core/Reference and UI regression checks with normal GC and explicit disposition of known environment-dependent cases.
3. Real PyInstaller onedir build, artifact validation and packaged smoke.
4. Portable ZIP build/smoke and Inno Setup installer build/install/run/uninstall smoke on an authorized Windows host, followed by strict bundle validation and release owner sign-off.

- Disconnected-UNC **startup** has an owner-observed Windows PASS after the Recent-path corrections. Packaged startup and blocked explicit Recent Open/cancellation scenarios are tracked separately under Issue #242; no unreported pass or timing guarantee is implied.
- The historical Windows `0x8001010D` faulthandler/COM diagnostic remains monitored under Issue #246. A printed diagnostic with pytest continuation is not by itself proof of an active Core crash or a permanent native fix.
- Broader native Qt lifecycle/crash investigation remains recorded under Issue #81. Release qualification must evaluate actual observed impact rather than silently suppressing exceptions.
- Enterprise PRIVATE service, authentication, sanctioned Handoff import/signature/manifest and product-specific full packaging remain downstream acceptance obligations (Issue #156). They are not Core release assertions.
